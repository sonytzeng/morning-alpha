## 最後兩項恢復修復（候選，未正式部署）

Canonical 的30秒等待原先被 Handler 的20秒延續上限忽略。現在只允許這個具名等待在120秒背景預算內交棒一次，預留5秒給既有3秒有界 Gateway 呼叫；Provider 的長退避不因此縮短，Core 不等待研究。隔離 HTTP Handler 控制已確認真正 sleep 30000ms 並呼叫一次 continuation，並非只測 runner 回傳狀態。

Checkpoint 中的216筆 locks 原本僅代表準備完成，不能證明 SQL 已提交。恢復時先驗證原始 hash，再以相同 bytes 重送 PREDICTIONS。既有交易式 SQL／Lease fence 才決定提交與冪等性：截止後已提交的相同資料可重試，未提交的資料仍拒絕，絕不倒填。只有具名 SQL 時間拒絕且已過截止，才標示 EXPIRED；其他 RPC／網路失敗仍為 BLOCKED。Adapter 僅保留這個安全錯誤碼，不輸出任意資料庫錯誤。任何提交失敗都不能跳到 COMPLETE 或 Outcome。

真 PostgreSQL／PostgREST／HTTP 的故障注入已驗證：提交前中斷為0筆；控制時鐘超過實際100秒 Lease 後正確提交216筆（不改 Lease 到期時間）；提交後回應遺失，再超過實際 Lease 並於截止後恢復仍只有216筆，Checkpoint／Prediction／Outcome Queue／Publication 指紋不變。既有最後一筆失敗全批 rollback、晚到拒絕、Owner／anon／free／paid 權限、到期 Outcome 與停用新執行入口回滾測試均保留。控制時鐘、身分與 Provider 只存在隔離環境，不能當成正式自然 PASS。

本修復不改 SQL、Auth、RLS、既有 Caller、正式研究方法、推薦門檻或業務資料；Release Manifest 的唯一 Migration 仍為同一候選檔。正式 Merge／Migration／新 Worker 與 Caller 部署仍需 Sony 對更新後 HEAD 具名核准。
